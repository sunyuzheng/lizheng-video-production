# 独立录音、长视频与社区回放交付

仅在用户提供独立 WAV、要求剪前导／压缩成片，或要创建社区活动回放草稿时读取。

这里是 agent 使用 ffmpeg、ffprobe 和平台工具完成的制作 recipe，不是 `process_video.py` 已自动实现的能力。每一步都应保存命令、参数与 QC 结果，不能因为 skill 描述了流程就声称文件已经完成。

## 双录音同步

机内声只做同步参考；用户指定独立录音时，最终节目音轨以独立 WAV 为准。

1. 每支 recorder 在前、中、后至少各取一个清晰语音或瞬态锚点。
2. 分别拟合 `external_time = offset + rate × camera_time`：offset 解决起点差，rate 解决录音设备时钟漂移。
3. 报告 offset、rate／ppm 与所有锚点残差。长视频不能只用开头一个 `adelay` 假设全程无漂移。
4. 用高质量重采样校正 rate，再按 offset 补静音或截取到 camera timeline。
5. 通过单人说话片段确认每支麦属于谁；轨道用人物名／角色命名，不交付含糊的 A、B。

目标残差可从单点 <20ms、平均 <10ms 起步，但以实际口型和听感为准；素材质量不足时如实记录，不伪造精度。

## 音频处理与 QC

- 检查 integrated loudness、true peak、削波、掉线、长静音、底噪和两人音色差；播客可从约 -16 LUFS、true peak ≤-1 dBTP 起步，再按平台和素材调整。
- 一支麦局部失真时，可在有交叉收音的另一支 WAV 上平滑接管，并记录时间段。用户明确不要机内声时，不偷偷混回机内轨。
- 输出后记录声道、采样率、响度、峰值、音视频时长差，并完整解码一次。

## 开头与统一时间基准

语义起点是第一句正式开场，不是波形第一次有声音。选择不会吞首字的干净画面点；字幕、VTT、章节和文章跳转时间统一映射到剪后 master 的 `00:00`。

如果用户要求去掉口头禅或假启动，先按 `filler-cut-editing.md` 建 reviewed edit plan；不要把剪前导和词级清理混成一组不可回退的手工操作。

## 社区版压制

先在操作当日确认目标平台的文件大小、codec、字幕和 thumbnail 要求。把平台上限当硬门而不是目标：例如上限为 4GB 时，可按约 3.8GB 预算，给容器 metadata、计量差异和重新上传留余量。

兼容性优先可从 MP4、H.264 High、yuv420p、1080p、AAC-LC 48kHz 开始；按成片秒数、音频码率与 mux 余量倒推视频码率。完成后至少验证：

- exact bytes、时长、分辨率、帧率、codec、声道；
- 首帧／首音频时间和 A/V 时长差；
- `ffmpeg -v error -i output.mp4 -f null -` 全片解码无错误；
- 在目标平台的真实上传／处理预览里可播放，VTT 与 thumbnail 可关联。

## 活动回放草稿

本地先准备：

1. 帖子标题与 meta title；
2. 通过 QC 的社区版视频、VTT 和 16:9 thumbnail；
3. substance-first 的伴读文章；
4. 真实时间戳章节；
5. 只有确实能推进讨论时才加入的问题。

平台操作时选择正确空间／分区，等待视频上传和处理成功，再关联 VTT 与 thumbnail。保持 draft；本地文件存在不代表平台已经收到。

公开发布、发送 email notification、群发或把草稿改成可见帖，都属于新的外部动作。执行前展示最终正文、资产、目的地、受众和通知状态，取得针对这份 payload 的明确批准。
