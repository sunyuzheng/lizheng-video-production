# 字幕精校与交付

仅在任务包含 KDB 字幕、VTT、长视频精校或字幕 QC 时读取。

## 一条时间轴

`.qwen.srt` 是原始记录，`.corrected.srt` 是全文精校稿，`.final.candidate.srt` 是重新断句后的诊断候选；只有通过 QC 才晋升为交付区的 `.final.srt` 和 `.final.vtt`。不要在 VTT 里单独改字；SRT 与 VTT 必须从同一 cue 列表生成。

精校优先处理会改变理解或传播的错误：人物、公司、产品、技术术语、数字、日期、否定词和同一实体的多种写法。屏幕录制可从可见 UI 补充 seeds，但不要只按文件名猜实体。

## 长视频

60 分钟以上默认给全文校对至少 900 秒。超时或模型失败时停止，不把 raw ASR 复制成 corrected 文件。字幕精校保留原话中的语气词、重复和不完整推理；如果任务确实要清理口头禅或 false start，转到口头禅剪辑流程，先修改成片，再按同一剪辑计划重映射字幕。

对较长材料做人工语境抽查：

- 每一处替换同时看前后 cue，避免搬词、重复和漏词；
- 全片抽查高频专有名词和数字，而不是只看模型报告的修改；
- `corrections=0` 不是质量证明；若画面或语境能确认错误，仍要修正；
- 拉丁词、人名和产品名不能从词中间断开。

## 断句与时间码

先把 ASR 的坏 cue 边界合并成时间窗口，再按句末标点、子句标点和词边界重切。默认每条可见字符不超过 20；它是显示上限，不是应当填满的目标。极长的不可拆拉丁词可保留并交给 QC 报告提示人工选择。

### 防止“机器合法，读起来很怪”

当 ASR／corrected 文本几乎没有标点时，规则 splitter 会退回词边界装箱；固定长度窗口再叠加 `max_chars`，可能产出大量 19／20 字或 23／24 字的 cue。它们可以通过解析、时长、重叠、字数和 CPS 检查，却把限定语、动作与宾语、完整句与下一次 false start 切散。这正是本质量门要拦截的失败模式。

自动生成的 candidate 若连续出现大量“接近字数上限、又没有语义标点”的 cue，`process_video.py` 必须停止晋升。这个筛查只证明存在或未命中特定风险，不证明语义已经正确：

- **触发风险**：对整稿做一次语义重断句和人工通读，不靠调大字数上限掩盖问题。
- **未触发风险**：仍抽查开头、中段、结尾，以及人物／产品名、数字和长句密集处。

风险触发后的修复顺序：

1. 以真实停顿和完整意思组织较大的上下文，不把内部的固定字符窗口当成语义边界。
2. 补必要标点并重新分 cue，让单条字幕本身可理解，或与相邻一条形成自然推进；不要留下明显悬空的修饰关系，也尽量不要拆散多词英文实体。
3. 只改标点、空格和 cue 边界。专有名词或听写错误应先改进 corrected 源；去除标点、空格和样式标记后，语义重断句的正文字符流必须与该源一致。
4. 将新边界映射回原时间轴，重新检查非正时长、重叠、显示时长、阅读速度和字数。
5. 对照视频通读。保留说话者真实的重复与假启动；需要删除时走成片剪辑流程，不在字幕里悄悄删掉。

默认 20 字确实会拆坏不可分实体或清楚的意义单元时，可以小幅提高本期上限；这是有理由的本期取舍，不是新的全局默认。运行 QC 时传入真实 `--max-chars`，报告必须记录该值。

剪掉前导或清理口头禅以后，字幕、章节和文章跳转时间都要映射到最终成片的 `00:00`，不能混用剪前时间。

## QC 硬门

默认交付门：

- 无法解析的 SRT block：0
- 非正时长：0
- cue 重叠：0
- 可见字符超过上限：0
- 时长短于 0.2 秒：0
- 阅读速度超过 25 字符／秒：0

```bash
cd <implementation_root>
venv/bin/python tools/subtitle_qc.py /path/to/video.semantic.reviewed.candidate.srt \
  --source-srt /path/to/video.corrected.srt \
  --check-boundary-quality \
  --promote-srt /path/to/video.final.srt \
  --write-vtt /path/to/video.final.vtt \
  --report /path/to/video_process/video.subtitle_qc.md \
  --max-chars 20
```

`--source-srt` 检查重断句是否只改变了标点与布局；`--check-boundary-quality` 会在机械等长边界风险触发时拒绝晋升。报告可以在失败时生成；`.final.srt/.final.vtt` 只有机器门通过且人工语义复核完成后才晋升为交付。主流程遇到 QC 失败应停止所有依赖最终字幕的内容步骤。

## 交付检查

1. `.qwen.srt` 与 `.corrected.srt` 留在工作区，corrected/final 不反写 raw；ASR 重跑失败时保留上一份 `.qwen.srt`。
2. `.final.srt` 和 `.final.vtt` cue 数、时间码和文本一致。
3. QC 报告属于本次运行，不是旧文件；报告中的字数、时长、CPS 阈值与本次实际运行一致。
4. 术语、数字、日期和人物名字在字幕、章节、高光与文章中一致。
5. 人工读过真实字幕流，不只看“通过”字样；导入目标剪辑软件或社区平台后再做一次实际预览。
